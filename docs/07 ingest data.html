7  Downloading data

Key Points

  • Be clear about where your data is coming from

  • Wrap up the ingest of your data into a function

Once you have set up your wrap project and got your documentation and logging in place, you can put together your analysis scripts. As discussed in chapter 02, you should make your code as modular as possible, wrapping different processes in functions, then sourcing and calling them from a central script.

The data for your wraps can come from a variety of sources. Ideally you want this data to be available in the same format each time you run your wrap, to avoid needing to rewrite. This can be from published sources, from a database, or the product of other analysis.

For the example in this book we will use data from the ONS api.

7.1 Data setup and loading ONS meta data

We start by adding the packages we will be using to the main.R script. Keeping the reading of your packages central means you only need to do it once.

We can use the librarian package to manage installation and reading of our packages. It handles the installation of packages from a variety of sources, so if you are using a packages from Github as well as CRAN, the process is streamlined.

The below code adds the packages we will need for the data ingest process. It loads httr2 for interacting with the api, purrr for simplifying the response, dplyr and tidyr for manipulating data, and DHSClogger from the DHSC Data Science Github for logging. We use the stock function here which makes sure they’re installed, but doesn’t load them. We load the packages at the top of the scripts in which they are used.

if (!requireNamespace("librarian")) install.packages("librarian")
librarian::stock(readr, httr2, purrr, tidyr, dplyr, DataS-DHSC/DHSClogger)

It is best practice to define parameters needed in your code in configuration files outside of the scripts themselves. This means you don’t have to touch the code when you need to change any parameter values.

In the DHSC Template, the main configuration file sits in the ./input directory and is called config.yml. A YAML is a human readable data serialization language, it is a useful method for storing parameters in an easily understandable way.

The below parameters are the ones we will use to access data from the ONS api. Some code below shows how we find appropriate values.

data_dictionary_url: "https://api.beta.ons.gov.uk/v1/datasets"

7.2 Get a list of data that can be extracted using this ONS API endpoint

We use the data_dictionary_url to a request a list of available data.

#load packages
library(httr2)
library(purrr)
library(tidyr)
library(dplyr)

    filter, lag
The following objects are masked from 'package:base':

    intersect, setdiff, setequal, union
# request the data dictionary from the ONS api endpoint
dictionary_list <- request(config$data_dictionary_url) |> 
  req_perform() |> 
  resp_body_json() |>
  pluck("items") 


get_dictionary_info <- function(x){
  
   bind_cols(
     x %>% 
       unlist(recursive = F) %>% 
       keep(names(.) %in% c("title", "id")) %>% 
       as_tibble(), 
    
    x %>% 
       pluck("links") %>% 
       pluck("latest_version") %>%
       pluck("href") %>% 
       as_tibble()
    ) %>%
    
  return()
}

dictionary <- map(.x = dictionary_list, .f = get_dictionary_info) %>%
  bind_rows()

7.4 Wrap in function

Now we have all the code we need we can wrap it up in a function to be sourced and called in our run_analysis.R script, making sure to add our Roxygen documentation.

#' Downloads a csv from the ONS API, and saves to input folder
#'
#' @param data_id a string of the name of the data set to download. This is stored in config.yml as config$data_id
#' @param data_url a string of the url of the data set to download. This is stored in config.yml as config$data_url
#'
#' @import dplyr
#' @import httr2
#' @import logger
#' @import readr
#' @import purrr
#' @import tidyr
#'
#'
download_data_from_ons <- function(data_id, data_url){
    
    download_url <- request(data_url) |> 
      req_perform() |> 
      resp_body_json() |> 
      pluck("downloads") |> 
      pluck("csv") |> 
      pluck("href")
    
    data <- read_csv(download_url)
    
    data_filepath <- paste0(config$output_dir, "/", data_id, ".csv")
    
    write_csv(df_data, data_filepath)
    
    logger$info(paste0("data output to: ", data_filepath))

    return(data)
        
}

The last steps are:

  • Add new functions to librarian line in main.R
  • Add a source to your new function to run_analysis.R
  • Add the function to your function in run_analysis.R
